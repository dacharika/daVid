# assets search returns hits in raw worker order — the one vector-search surface that never re-ranks like transcript search does
cutvec's stated determinism contract is that the Go layer re-ranks worker output into a stable total order rather than trusting worker iteration order. searchCmd enforces it: cmd/cutvec/main.go:985 'ranked := project.RankCandidates(hits)', with the comment at main.go:982-984 calling this 'the determinism the acceptance criterion pins' (task 014). assetsSearchCmd does NOT: cmd/cutvec/assets.go:248-262 loops 'for _, raw := range list' over resp.Result["assets"] and appends each assetHit to out.Assets IN WORKER ORDER — no project.RankCandidates, no sort by Score, no cap to req.Limit (the limit is only passed to the worker at assets.go:239). So 'assets search' — the library/SFX/b-roll retrieval half of the headline 'vector search reproduce a full podcast edit' capability — emits candidates in whatever order the search worker's result map yields, and if that worker (or a future one) returns hits unsorted or with tied scores in nondeterministic order, two identical asset searches over one index return differently-ordered results. This is the SAME class of defect the panel accepted for shorts (task 034) and search (task 014): a query surface that trusts worker order instead of enforcing the descending-Score total order in Go. IMPACT: 'search' (transcript) and 'assets search' (library) disagree on whether ranking is deterministic; an agent picking 'the top SFX' gets a non-guaranteed order. LATENT/GREEN: there is NO assets-search test at all — assets_test.go (cmd/cutvec/assets_test.go:1-48) covers only describeAsset and parseOnePositional; no test asserts assets ordering, so the defect ships green. UNIT-TESTABLE with no melt/lancedb: drive assetsSearchCmd with a fake search worker (mirroring main_test.go's fake) that returns assets OUT of Score order (e.g. {score:0.2} before {score:0.9}) and assert out.Assets[0].Score is the highest — currently fails to sort. FIX: sort out.Assets by descending Score with stable tiebreaks (Ref, Text) before emitting, and cap to req.Limit in Go, mirroring searchCmd's RankCandidates+cap.
